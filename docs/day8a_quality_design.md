## 1. 超时与取消的实际审查

### 旧执行逻辑

Day 7A 路由同步执行服务。服务使用两格 `BoundedSemaphore`；原离线适配器启动固定冻结 worker，`subprocess.run(timeout=180)`。前端 `AbortController` 在 25 秒停止等待。

原并发槽确实在 `finally` 释放，但浏览器取消不是 worker 的取消信号。客户端停止等待后，计算可能仍占用子进程与槽位，最长延续原 180 秒期限。用户手动再提交会产生另一项计算；原前端没有自动重试，本轮也没有增加重试。不能把前端 Abort 当作后端已停止。

### 最小修复

```text
浏览器取消 / 25s 客户端等待上限
  → Vite 代理关闭该请求对应的上游连接
  → 外层纯 ASGI 中间件捕获 http.disconnect
  → 请求专属 Event
  → 同一固定冻结 worker 的可取消运输适配器
  → kill / communicate / wait / 关闭管道
  → service finally 释放并发槽
```

网页 worker 使用 20 秒期限；路由监控 22 秒期限并等待清理；客户端保留 25 秒等待上限。轮询间隔 50ms，正常清理窗口 2 秒。只终止该请求自己启动的子进程，不枚举或删除其他进程；不重试、不提前释放槽位、不遗弃正常可终止的计算。返回安全中文 504/499。

原 180 秒批量离线适配器保持原样。网页运输改为调用同一个原 worker、原签名校验、原严格响应模型，没有复制后改写算法。

**真实探针发现并修复的额外问题：**仅靠路由 `Request.is_disconnected()` 的初版模拟测试通过，但真实 HTTP 断连失败。`BaseHTTPMiddleware` 的接收循环可能先消费断连事件。现在在最外层纯 ASGI 中间件记录事件；Vite 的共享代理处理器监听 response `close`，在响应未完成时销毁对应上游请求。必须监听响应等待阶段，不能仅监听 POST 请求体的 `aborted`。

实际回环 HTTP 探针覆盖直接 ASGI、共享 Vite 取消处理器代理、压缩期限 504及进程关闭。子进程是测试专用 30 秒 sleeper；未替换生产算法。最后复跑直接/代理取消到释放分别约 0.082/0.061 秒；各仅启动一次子进程，两个槽均恢复、管道关闭。见 `day8a_cancellation_probe_results.json`。另以真实 Chrome 验证取消按钮、重复提交禁用、无自动重试与无旧结果残留。

**边界：**20/22/25 秒是受控执行政策，不是操作系统故障下的硬实时保证。不可中断的文件 I/O、同步注册校验或极端 OS 进程回收卡顿可能延长清理；此时保留槽直到工作退出，不宣称已释放。探针代理使用与 Vite 相同的处理器，但不是未来生产反向代理。正式 HTTPS 部署仍须单独验收断连传播及整个请求生命周期。

## 3. 新问事应用管线（仅离线）

```text
原受控适配器：冻结计算 + 已批准 Frame + 可靠来源
  → 服务自行读取 Day7A 固定资格/判断
  → 受封印 QualityRequest
  → QuestionIntent：原问题精确片段、事实/转述/意图/未知分别记录
  → 四角色应用草稿：Frame 原子 + 原问题片段 + 全部限制 ID
  → 确定性绑定/安全/已知来源限制检查
  → 独立核验器：另一个请求，读取完整依据和草稿
  → 六项全部通过、score≥3、receipt 指纹完全绑定
  → 程序渲染：原批准卦义 + 显式现实应用类比 + 全部限制
失败 → 原已批准基础卦义，不重试、不改卦、不写历史
```

该实现不改旧 `question_interpretation_v2`、旧签名、缓存或历史。六项检查与 score≥3 的门槛没有降低。仅不同 Mock 对象是“独立请求隔离”的接口演示，不能证明同一真实厂商的判断彼此独立。

不根据 user question 更新卦象；模型不得声明体用、五行旺衰、方向、资格或最终吉凶。未审核爻位只允许已有基础 Frame 的条件性应用，不允许生成扩展综合裁决。

## 4. 来源限制与现实事实

- “对方说工作忙”只记录用户转述，不能认定对方真实动机。
- “想重新做生意”是意图，不能推定已有库存、门店、租金、订单、收入或推广计划。
- 用户提到下周/今年，应记录时间窗口；不能转化为预测截止日。
- 五行时令不是心理稳定、能力强或现金充足等现实事实。
- `preserved_limit_ids` 必须完整等于原 Frame 与 Day7A 对应条件/限制集合。程序渲染原限制全文，状态保持未核实。
- 原典条件与现实应用不是同一层，不能把类比写成古籍直接作出的现实结论。

旧 Q14 的短 Frame 只写“相遇”，而原典有“勿用取女”的限制。新增固定、**只拒绝不批准**的应用范围记录 `data/day8a_application_scope_holds.json`：绑定批准原子哈希、来源指纹和已核验文本。应用层自动退回基础卦义；不修改原 Frame，不撤销原 Day7A 资格，不自动生成新条件。缺失/篡改范围记录也回退。规范内容哈希兼容 Windows 换行。
