# Day 4 API 整合计划（未执行）

## 计划范围

仅建立冻结梅花模块的最小服务适配层：手动本卦/爻位/时间，以及独立时间起卦入口。默认手动输入，问题不能改变卦象。

## 预备接口契约

- 请求字段白名单：输入模式、本卦 ID、动爻位置、带时区的时间；问题上下文留在解释层。
- 输出：本卦、动爻名称/位置、互卦、变卦、体用、五行生克、月建/旺衰、来源引用、规则版本。
- 采用独立 adapter 调用现有受控服务，不改生产源码或冻结算法。
- 读取生产历史只走受控历史接口，不直接用网页业务代码连接生产 SQLite；调试/测试使用隔离库。
- 导入方式必须防止向生产路径写 pycache，依赖版本与签名/指纹必须兼容。
- 已批准 SemanticFrame、原典、source verification 不因新请求重新生成或改写。

## 验收顺序

1. Mock adapter 与 API 输入校验，禁止任意 Python 模块/SQL/prompt 参数。
2. 固定黄金案例：观六四 → 互剥 / 变否；随六二 → 互渐 / 变兑。
3. 同一卦、同一时间，改变问题不改变任何确定性字段。
4. 原服务版本、来源、签名、缓存与快照回放契约逐项确认。
5. 无法安全适配时显式失败/使用现有标准回退，不启用临时 AI 断卦。

Day 4 不以 Day 3 连通性诊断类生成正式解读。`question_interpretation_v2` 的原独立核验及回退仍需保留；旧最终验收的语义 FAIL 必须公开保留，不能靠换网页宣布通过。

后续问事和自然解读接入属于 Day 5 及单独质量修复阶段；未经审核正文不得流式展示。`traditional_judgement_v1` 尚未实现，不得宣称完成。
