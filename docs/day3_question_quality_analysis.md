## 问题与建议（本轮均未实现）

| 原问题 | 失败原因 | 保持旧数据不变的修复方向 | 应验证的证据 |
| --- | --- | --- | --- |
| F-01 隐含结果保证 | 否定式或避免式表达绕过直接预测约束；独立核验仍误批 | 在新的应用适配层检查每一条结果断言及其否定/保证表达；失败回退，不降低原阈值 | 已发现的隐含保证样例及未见过的同义改写必须拒收 |
| F-02 未提供事实被推定 | 条件词作用范围错误，另一分句中的条件不能许可现状断言 | 使用用户原话位置绑定事实；逐分句区分事实、假设、建议，不把行业常见事项当作用户已发生事实 | 对未提供支出、回款、对方过失等拒收；真正的显式假设仍可识别 |
| F-03 类比增添古义条件 | 模型把现实问题附会为源文本的新前提，核验没有发现 | 应用陈述绑定 Frame/source 原有条件；无法证明条件继承时仅显示基础解读 | 原义没有的前提、条件不成立断言不能被批准 |
| F-04 时间误报缺失 | 意图抽取没有正确区分明确未来时间和过去背景 | 从问题原话提取未来窗口、过去事实和愿望，保留原话跨度 | “下周/今年”不能报为未提供；过去认识时长不能冒充未来窗口 |
| W-01 同模型核验误批 | 六项 true 与 score≥3 属于协议结果，不能证明真实语义正确；同厂商核验错误有相关性 | 原门槛保持；增加来源跨度、事实及条件一致性检查，另做保留集抽查，不把单个 verifier 分数当充分保证 | 原典独立抽查须覆盖已发现误批和新问题，报告真实批准率/回退率 |
| W-02 短 Frame 省略限制 | 应用继续放大被压缩的卦义 | 不改已批准 Frame；在新版本应用层读取现有原文限制作为只读约束，不能可靠绑定时回退。完整 Frame 改版需另立版本及授权 | source 限制与应用条件可追溯，旧历史不被重新解释 |
| W-03 失败无缓存 | 反复提交失败问题重复消耗 API | 在独立网页服务设计短期失败缓存，键绑定问题、卦象、时间、政策版本及证据指纹；过期/版本更新再尝试 | 成功与失败命中均零调用；不改旧生产缓存和历史 |
| W-04 可读性不足 | 古语堆叠、篇幅过长、重复泛化，未解决用户具体关心的事 | 仅在批准应用层压缩表达，区分一条主要观察与有限行动提示；保留出处和条件，不重释古籍 | 普通读者可读性检查；可读性提升不能牺牲事实/来源一致性 |
| W-05 意图粒度粗 | 已提供部分信息仍被归为整类缺失；愿望被当成事实 | 设计有原话锚点的意图细项，分别标注已知、未知和用户目标 | 对模糊问题不追认背景，对具体问题不误删已知事实 |
| W-06 时令被读成现实状态 | “体平”等标签被表达为用户心理或事业已知状态 | 新网页解释展示明确这些是传统时令关系的描述，不能作为现实事实；不改旧 renderer/历史定义 | 不推断精神状态、经济情况或事件结果 |

F-01～F-04 在旧报告中已有必要模式保护；上述建议针对剩余可靠性与泛化问题，不宣称它们当前均未修复，也不宣称已彻底解决。

## 后续验证顺序

1. 先复用冻结计算、只读证据和标准解读 API；不启用自由应用正文。
2. 给新的网页应用层定义事实/来源/条件绑定契约，保留受控请求、签名与回退。
3. 离线复现原 F/W 样例，加上未见过的分句、否定、时间与类比变体。
4. 做受控失败缓存与逐字历史回放测试，生产历史只读。
5. 得到单独授权后，才进行小量真实应用验收；不要批量重跑此前付费案例。

本报告是修复方案。没有实现新的问事模型、来源限制层、失败缓存或旧数据改版。
